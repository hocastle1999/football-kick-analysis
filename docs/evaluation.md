# 평가 기록

모델을 바꾸기 전에 "지금 얼마나 맞는지"를 믿을 수 있게 재는 방법부터 만들었다.
여기 있는 표는 모두 `scripts/evaluate.py`로 다시 만들 수 있다.

표의 수치는 정밀한 포즈 모델로 영상 전체를 뽑은 키포인트로 잰 것이다.
저장소의 `data/keypoints/`는 그 뒤 속도 개선으로 바꾼 2단계 추출의 결과라서 다시 돌리면 값이 조금 다르게 나온다.
두 데이터의 차이는 [performance.md](performance.md)의 3번 표에 있다.

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate --task impact
.\.venv\Scripts\python.exe -m scripts.evaluate --task foot
.\.venv\Scripts\python.exe -m scripts.evaluate --task foot --exclude-label aligned
```

## 1. 데이터

| 묶음 | 영상 | 촬영 | 사람 |
|---|---|---|---|
| 무게중심, 논문에 쓴 것 (`thesis63`) | 63개 (클래스당 21) | 1280×720, 24fps | A, B, C (각 21개) |
| 무게중심, 추가 촬영 (`extra60`) | 60개 (클래스당 20) | 1920×1080, 30fps | C, D, E |
| 디딤발 (`thesis50`) | 50개 (클래스당 10) | aligned만 720p 24fps, 나머지는 1080p 30fps | aligned는 B, C / 나머지는 D, E |

사람 구분은 영상마다 임팩트 장면을 뽑아 옷차림을 보고 정했다. 번호와의 대응은 다음과 같다.

- 무게중심 논문 영상: 1~7번 A, 8~14번 B, 15~21번 C
- 무게중심 추가 영상: 22~31번은 back과 front가 D, middle이 C / 32~41번은 E
- 디딤발: aligned 1~3번 B, 4~10번 C / 나머지 클래스는 1~5번 D, 6~10번 E

## 2. 평가 방식

논문은 무작위로 60/40으로 한 번 나눠 테스트 20~26개로 정확도를 쟀다. 이 방식의 문제는 두 가지다.

1. 테스트가 적어 영상 하나가 4~5%p다. 나누는 방법에 따라 결과가 크게 달라진다.
2. 같은 사람이 학습과 테스트에 함께 들어간다. 자세가 아니라 사람(체형, 옷, 서 있는 위치)을 외워도 점수가 나온다.

그래서 세 가지로 잰다.

| 이름 | 방법 | 알 수 있는 것 |
|---|---|---|
| 반복 교차 검증 | 5조각으로 나눠 돌아가며 시험하기를 5번 반복, 평균 ± 표준편차 | 같은 사람, 같은 촬영 조건에서의 성능 |
| 사람 단위 | 한 사람의 영상을 전부 빼고 학습한 뒤 그 사람으로 시험 | 처음 보는 사람에 대한 성능 |
| 63 → 60 | 논문 영상 63개로 학습하고 추가 영상 60개로 시험 | 촬영 날짜와 해상도가 달라졌을 때의 성능 |

## 3. 무게중심 결과 (영상 123개, 5명)

| 방법 | 반복 교차 검증 | 사람 단위 | 63 → 60 |
|---|---|---|---|
| 논문 방식: 화면 좌표 + LSTM 50에폭 | 0.75 ± 0.02 | 0.56 | 0.77 |
| 화면 좌표 + LSTM 300에폭 | 0.96 ± 0.00 | 0.60 | 0.62 |
| 새 임팩트 + 화면 좌표 + LSTM 300에폭 | 0.95 ± 0.02 | 0.55 | 0.55 |
| 새 임팩트 + 정규화 좌표 + LSTM 300에폭 | 0.94 ± 0.02 | 0.69 | 0.83 |
| **새 임팩트 + 정규화 자세 1장 + 로지스틱 회귀** | **0.97 ± 0.00** | **0.76** | **0.95** |
| 새 임팩트 + 기하 특징 3개 + 로지스틱 회귀 | 0.82 ± 0.01 | 0.72 | 0.75 |

사람 단위 평가를 사람별로 보면 다음과 같다.

| 방법 | A | B | C | D | E |
|---|---|---|---|---|---|
| 논문 방식 | 0.38 | 0.67 | 0.52 | 0.10 | 0.97 |
| 정규화 좌표 + LSTM | 0.67 | 0.67 | 0.65 | 0.65 | 0.80 |
| 정규화 자세 + 로지스틱 회귀 | 0.62 | 0.71 | 0.81 | 0.65 | 0.93 |

읽는 법:

- **에폭을 늘리면 교차 검증 점수는 오르지만 처음 보는 조건에서는 오히려 떨어진다** (0.77 → 0.62).
  화면 좌표를 그대로 쓰면 모델이 "화면 어디에 서 있는지" 같은 촬영 조건을 외우기 때문이다.
- **좌표를 공 기준으로 정규화하면 처음 보는 조건에서 오른다** (LSTM 0.62 → 0.83).
- **LSTM보다 로지스틱 회귀가 세 평가 모두에서 높다.** 영상이 100개 남짓이라 가중치가 많은 모델이 유리하지 않다.
  LSTM은 6프레임 × 66값을 받아 가중치가 3만 개가 넘고, 로지스틱 회귀는 66값에 가중치 201개다.
- 사람 단위 0.76은 여전히 낮다. 사람마다 "뒤로 기울인다"의 정도가 달라서, 사람 수(5명)가 가장 큰 제약이다.

채택: **새 임팩트 + 정규화 자세 1장 + 로지스틱 회귀**. 분석에 쓰는 모델은 123개 전부로 학습한다.

5클래스 전체 (영상 50개):

| 방법 | 반복 교차 검증 | 사람 단위 |
|---|---|---|
| 논문 방식: 화면 좌표 + LSTM 50에폭 | 0.71 ± 0.04 | 0.46 |
| 화면 좌표 + LSTM 300에폭 | 0.85 ± 0.02 | 0.62 |
| 새 임팩트 + 정규화 좌표 + LSTM 300에폭 | 0.89 ± 0.02 | 0.30 |
| 새 임팩트 + 정규화 자세 1장 + 로지스틱 회귀 | 0.84 ± 0.03 | 0.52 |
| 새 임팩트 + 왼발 위치 6개 값 + 로지스틱 회귀 | 0.73 ± 0.02 | 0.48 |

aligned를 뺀 4클래스 (영상 40개, D와 E 두 사람):

| 방법 | 반복 교차 검증 | 사람 단위 |
|---|---|---|
| 논문 방식: 화면 좌표 + LSTM 50에폭 | 0.72 ± 0.07 | 0.47 |
| 화면 좌표 + LSTM 300에폭 | 0.82 ± 0.06 | 0.45 |
| 새 임팩트 + 정규화 좌표 + LSTM 300에폭 | 0.88 ± 0.02 | 0.57 |
| 새 임팩트 + 정규화 자세 1장 + 로지스틱 회귀 | 0.88 ± 0.03 | 0.68 |
| **새 임팩트 + 왼발 위치 6개 값 + 로지스틱 회귀** | 0.84 ± 0.04 | **0.75** |

### aligned 클래스는 촬영 조건으로 구분되고 있었다

aligned 영상 10개만 다른 날, 다른 자리에서, 다른 사람이 찍었다(해상도와 배경도 다르다).
화면 좌표를 쓰는 모델은 사람을 빼고 학습해도 aligned를 100% 맞히는데(B 1.00, C 1.00),
촬영 조건의 영향을 없앤 정규화 좌표로는 하나도 못 맞힌다(B 0.00, C 0.00).
즉 aligned를 맞힌 근거는 디딤발 위치가 아니라 "어느 날 찍은 영상인가"였다.
논문에서 aligned의 정밀도와 재현율이 늘 1.00이었던 것도 이 때문으로 보인다.

채택: **새 임팩트 + 왼발 위치 6개 값 + 로지스틱 회귀** (4클래스 사람 단위에서 가장 높다).
다만 aligned를 같은 조건으로 다시 찍기 전에는 5클래스 결과를 믿기 어렵다.
웹 화면에는 디딤발 판정이 참고용이라는 안내와 분류 확률을 함께 보여 준다.

## 5. 임팩트 추정을 바꾼 이유

논문 방식은 "오른발 끝과 공 중심이 가장 가까운 프레임"이다. 영상을 프레임별로 확인하니 문제가 둘 있었다.

- 24fps에서 차는 발은 한 프레임에 화면 폭의 15% 안팎을 움직인다. 실제 접촉은 두 프레임 사이에 있어서,
  영상에 따라 접촉 직전 프레임이 잡히기도 하고 직후 프레임이 잡히기도 했다.
  새 방식(접촉 직전 프레임)과 비교하면 173개 중 논문 방식이 같은 프레임인 것이 30개, 1프레임 뒤가 112개,
  2프레임 뒤가 28개다. 나머지 3개는 3~11프레임 앞을 잡았다.
- 공이 잡힌 프레임 안에서만 찾았다. 공 검출률은 평균 50% 정도이고 영상에 따라 3%까지 떨어진다.

새 방식(`impact.find_impact`):

1. 공이 검출된 위치 중 가장 많이 모여 있는 곳을 "차기 전 공의 자리"로 정한다.
2. 차는 발끝이 그 공의 가까운 쪽 가장자리를 지나가는 구간을 찾는다.
3. 구간의 앞뒤 프레임 사이에서 지나가는 시점을 선형 보간으로 계산한다(예: 23.4번째 프레임).
4. 그 시점의 관절 좌표도 앞뒤 프레임을 같은 비율로 섞어 구한다.

173개 영상 모두에서 임팩트를 찾았고, 발끝이 공을 지나가지 않아 예비 방법(가장 가까운 프레임)을 쓴 것은 2개다.
정답 프레임을 따로 표시해 둔 것이 없어서 임팩트 추정 자체의 오차는 수치로 재지 못했다.
추가 영상 60개의 접촉 직후 프레임을 눈으로 확인했을 때 발이 공에 닿아 있었다.

## 6. 남은 문제

- **라벨과 킥 종류가 겹친다.** 추가 영상 60개는 롱 패스가 전부 back, 슈팅이 전부 front, 짧은 패스가 전부 middle이다.
  모델이 무게중심이 아니라 킥 종류의 다른 특징(발의 높이, 스윙)을 보고 맞혔을 수 있다.
  실제로 무게중심 분류기에서 가중치가 가장 큰 관절은 차는 발끝이다(`scripts/feature_importance.py`).
  같은 킥 종류 안에서 무게중심만 바꿔 찍은 영상이 있어야 가려낼 수 있다.
- **사람이 5명뿐이다.** 사람 단위 정확도(0.76)를 올리려면 모델보다 사람 수를 늘리는 쪽이 효과가 클 것이다.
- **분류 확률이 실제보다 높게 나온다.** 학습 데이터에 대한 정확도가 0.99라 확률이 1에 가깝게 나오는 경우가 많다.
  확률을 "맞을 가능성"으로 읽으려면 보정이 필요하다.
- **디딤발의 너무 가까움 / 너무 멂**은 카메라에서 멀어지는 방향의 차이라 옆에서 찍은 영상으로는 구분이 어렵다.
